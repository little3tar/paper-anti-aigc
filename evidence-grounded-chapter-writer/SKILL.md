# Evidence Grounded Chapter Writer

在 thesis outline 或章节目标已经明确后使用本 skill。目标是写出有证据边界的章节草稿，而不是为了让正文完整而编造事实、参数、公式或文献。

## 工作流程

1. **确认写作目标**
   - 确认章节编号、节范围、预期字数、引用样式和输出格式。
   - 独立一次性问答未指定输出格式时，默认在对话中输出 Markdown；真实论文工作流中应同步更新 `.thesis-workflow/02-chapter-draft.md`。
   - 单独运行本 skill 时，若当前目录、用户指定目录或已识别的论文项目根目录中存在 `.thesis-workflow/`，或用户明确处于论文 workflow 项目中，结束时必须更新 `.thesis-workflow/02-chapter-draft.md` 和必要的 `project-ledger.md`；不要因为用户没有再次说“生成文件”而跳过更新。
   - 只有当格式会影响工作时才问：“请确认本章输出格式：直接对话 Markdown、`.md` 文件，还是 `.docx` 文件？”
   - 进入论文项目工作流后，默认写入或更新论文项目根目录下的 `.thesis-workflow/02-chapter-draft.md`；不要写入 skill 仓库。若当前目录无法判断论文项目根目录，先确认保存位置。
   - 未指定拆分方式时，把章节细纲、证据表、正文、图表占位符、待补材料和后处理建议统一写入一个默认主文件，例如 `.thesis-workflow/02-chapter-draft.md`。
   - 如果需要直接修改已有论文主文件，修改前先备份该主文件；复制备份默认放在 `.thesis-workflow/backups/`，备份位置和文件名写入 handoff 或 project ledger。修改完成后仍要把本轮章节结果另存或同步到 `.thesis-workflow/02-chapter-draft.md`。
   - 如果存在 project ledger，先读取；如果 `.thesis-workflow/` 已存在或任务会跨多个章节，主动创建或更新 `.thesis-workflow/project-ledger.md`，只有保存位置或是否使用文件不明确时才询问。

2. **生成章节细纲并等待确认**
   - 把章节拆成节、小节和段落级写作点。
   - 标出每个写作点需要的文献、公式、设计假设、图、表或用户数据。
   - 涉及建模、计算、选型、实验、仿真、算法或定量比较时，标出预期的公式/参数工作。
   - 不要在用户主题和证据尚未要求时强行加入领域公式。
   - 除非用户明确要求连续执行，否则完整起草前先等待细纲确认。

3. **检索和整理证据**
   - 优先使用 Zotero MCP 或本地文献 MCP。
   - 如果不可用，检查本地 `.bib`、`.ris`、`.csv`、文献清单或用户材料。
   - Web search 只用于补缺口，并优先选择可靠来源。
   - 章节涉及行业标准、国家标准、规范、规程、验收要求或限值时，先查本地文献和用户材料；不足时主动搜索官方标准平台、主管部门、标准发布机构、出版社页面或其他可靠来源。
   - 起草前为本章建立小型证据表：题名、作者/年份、来源类型、可支撑的论点、对应段落。
   - 已核验的标准规范应作为正式支撑来源写入证据表，标明标准名称、标准号、版本/年份、发布机构和适用条款或范围。

4. **撰写章节正文**
   - 使用中文工程论文风格。
   - 在需要正式引用的位置插入 `[参考文献]`。
   - 在被支撑论点附近或证据表中保留 title-based source marker，方便后续 bibliography 解析。
   - 将 `[此处插入图片：...]` 和 `[此处插入表格：...]` 放在正文第一次需要出现图表的位置；尾部清单只能汇总，不能替代正文插入点。
   - 公式统一用 LaTeX math，便于在 Markdown、LaTeX 和 Word/MathType 流程之间迁移。
   - 工程计算段按“公式、符号表、参数来源表、代入、结果、单位检查、设计裕量”展开。
   - 缺少证据或参数时，不把 unsupported fact、parameter、formula 或 conclusion 写入正文；记录到 `未写入正文的待补资料`、`证据缺口清单` 或 project ledger。
   - 后续章节需要用户自制材料时，直接列入 `待用户补充的信息`，例如图纸、结构尺寸、实验记录、仿真截图、程序输出、设备选型依据、现场照片或导师批注；不要用常识替用户补造。
   - 已核验的标准规范应融入正文表达，用于支撑设计参数、限值、选型依据、验收要求或安全裕量。正文中写明标准名称、标准号、版本/年份和适用范围，并保留 `[参考文献]` 或最终模板要求的引用格式。
   - 未核验的标准规范只保留在 `证据缺口清单` 或工作稿 source note 中，不写成正文定论。
   - 区分 `影响关系` 和 `可计算公式`：概念关系式可说明变量影响方向；可计算公式必须有来源、符号定义、参数值、代入、单位检查和结果。
   - 用户确认的假设只有在明确标为 `[设计假设: ...]` 时才进入正文。
   - 新确认的事实、参数、公式或设计决策，应写入或准备写入 project ledger，而不是只留在聊天记录里；未经用户确认的内容只能作为 draft、needs-source 或 needs-user-data 记录。

5. **完成章节交接**
   - 提供来源清单、未支撑项、需要用户补充的数据和推荐下一步。
   - 推荐先运行 `reference-integrity-auditor`，再进入 `engineering-paper-humanizer` 和 `academic-format-cleaner`。

## Source Marker 规则

生成 reference placeholders 或来源表时读取 `references/citation-key-rules.md`。

章节涉及公式、参数、建模、推导、计算、设计选型、实验/仿真数据、算法或定量比较时读取 `references/formula-calculation-rules.md`。

使用或更新已确认项目事实、公式、来源和设计决策时读取 `references/project-ledger-rules.md`。

工作稿统一使用这些标记：

- 正式引用占位：`[参考文献]`
- Zotero/local source marker：`[文献题名]`，例如 `[基于神经网络的悬臂式掘进机自适应截割控制系统研究]` 或 `[A development in rock cutting technology]`
- 网络来源：`[网络资料: 检索词或网页标题]`
- 标准规范工作标记：`[标准规范: 标准号或规范名称]`，仅用于起草和核验阶段；核验后应转为正文中的正式依据和 `[参考文献]`
- 用户材料：`[用户材料: 文件名或材料名]`
- 缺失证据：放入 `未写入正文的待补资料` 或 `证据缺口清单`，不要把 `[待补来源: ...]` 留在正文中。

题名规则：

- 中文文献使用原中文题名。
- 英文文献使用原英文题名，不要强行小写、去空格或改写。
- 如果题名重复，在 marker 内追加作者和年份，例如 `[A development in rock cutting technology Hood 2000]`。

## 输出模板

完整章节草稿默认返回：

1. `章节细纲`
2. `证据表`
3. `公式与参数计划`
4. `正文初稿`
5. `图片与表格占位符清单`
6. `参考来源清单`
7. `待用户补充的信息`
8. `未写入正文的待补资料`
9. `证据缺口清单`
10. `后处理建议`

如果用户已经批准直接起草，可以省略确认停顿，但仍必须把 unsupported items 放在缺口区，而不是写进正文。

## 缺参数章节模板

当章节需要计算但任务书缺少参数时，使用这个结构：

1. 说明设计目的和当前数据边界。
2. 提供参数来源表，列为 `参数`、`含义`、`来源状态`、`备注`。
3. 不可用数值不进入正文，列入 `未写入正文的待补资料`。
4. 只有用户明确确认后才使用 `[设计假设: ...]`。
5. 概念性内容放在 `影响关系`；可计算内容放在 `可计算公式`。
6. 每个可计算公式都包含来源、符号、代入、结果、单位检查和裕量；缺任一项时，只作为公式计划，不写计算结论。
