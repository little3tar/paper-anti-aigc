# 重写指南：工程类学术文本去 AI 化

> 本文件是 engineering-paper-humanizer 的核心改写策略。包含正文改写规则、工程语气指南和通用中文标点原则。
>
> **拆分说明**：本 skill 现在只处理正文内容和通用中文标点。LaTeX/Markdown/txt 专属格式问题已迁移到 `academic-format-cleaner`。
>
> **注意**：AI 敏感词替换字典和快速检查清单已移至 `scripts/text_rules.json`，运行 `python scripts/check_text.py <file>` 即可获取完整检测。

## Part 1：五大核心规则分类

> **重构说明**：原十五个维度按工程写作的实际问题类型重新归为五大类，每类包含 3-4 条具体规则。规则顺序不再固定，可按需交叉引用。

### 一、内容逻辑类（Content & Logic）

本 skill 的核心不是把文字改得更高级，而是在事实、参数和引用不变的前提下，把表达改成普通本科论文里常见的平实写法。句子可以不那么漂亮，可以多一点“的、了、这个、这样”，但意思要接得上。

#### 规则 L1：重塑”僵化逻辑”与”过渡句式”

**敏感词**：虽然...但是、因此、然而、此外、综上所述、总而言之、由此可见、不难发现

**操作**：

- 不要把“虽然...但是”全改成很干净的判断句，可以拆成两句，也可以写成“不过这里还存在……的问题”，让语气更普通。
- 连接词不要成套出现。不是简单删除，而是换成更日常的承接，如“这里”“这样一来”“后面计算时”“所以在设计里”。
- **三段式警戒**：AI 生成文本倾向于用“X、Y、Z”三连描述制造节奏感（如“响应快、出力大、精度高”）。正文要减少这种整齐结构，能写成“响应速度还可以，出力也比较大，控制精度方面基本能满足要求”时，就不要压成三个并列词。

#### 规则 L2：重构“文献综述”起手式

**敏感词**：现有研究表明、大量文献指出、国内外学者普遍认为、国内起步较晚、研究尚处于起步阶段

**操作**：

- ❌ “现有研究表明...” → ✅ “某某在文献中提到...”或“从这些研究可以看出...”。不要每一段都用“某学者指出”，这种句式也会显得整齐。
- ❌ “国内起步较晚...” → ✅ 改成“国内这方面的研究相对少一些，近几年才开始围绕XXX做一些分析”，语气可以普通一点。

#### 规则 L3：消除“模糊归因”与“虚假权威”

**敏感词**：众所周知、业内公认、专家认为、有关研究表明、大量实验证明、普遍认为、据报道

**操作**：

- 具体化归因 → “众所周知”“业内公认”“专家认为”这类说法要改掉，优先写成“某文献中提到”“相关试验中给出了……结果”。
- 清理虚假权威 → 没有数据支撑的“大量实验证明”不要保留，可以改成“已有试验里有类似现象”，但不要把话说满。

#### 规则 L3a：文献引用真实性红线（⭐ 新增）

> ⛔ **绝对禁止编造文献引用**

**操作原则**：

1. **引用溯源义务** → 若改写引入新的 `\cite{}` 引用，必须获取并验证真实文献内容
2. **相关性审查** → 引用的文献必须与前后文论述直接相关，不能是随机套用
3. **无真实文献时** → 删除相关模糊表述，改用客观事实陈述

**具体禁令**：

- ❌ **禁止虚构引用键名** → 不允许编写如 `\cite{zhang2020}`、`\cite{ref1}` 等虚假键
- ❌ **禁止编造作者** → 不得捏造“Smith et al.”、“李明等”等不存在的作者
- ❌ **禁止套用无关文献** → 不要将完全不相关的文献强加到论述中
- ❌ **禁止伪造年份** → 不得虚构“根据 2023 年张三的研究...”

**执行策略**：

| 场景 | 处理方式 |
|------|----------|
| 宿主文档已提供文献信息 | 复用现有 `\cite{}` 键名和作者 |
| 用户提供了真实文献列表 | 按用户要求添加真实引用 |
| 无任何文献依据 | 删除模糊归因，改用客观陈述 |
| 不确定是否存在相关文献 | 改为“相关研究表明”或直接删除 |

**改写示例**：

**❌ 错误（虚构引用）：**
```latex
王教授等\cite{wang2023}指出，该系统在高负载下表现优异。
```

**❌ 错误（套用无关文献）：**
```latex
该算法有效\cite{smith2024}，显著提升了性能。（注：smith2024 是一篇关于基因组学的论文）
```

**✅ 正确（无真实文献时改为客观陈述）：**
```latex
测试表明，该系统在额定负载 120\% 工况下仍能保持稳定输出。
```

#### 规则 L4：消除“提纲式挑战”部分

**操作**：

- ❌ “尽管取得了进展，但系统仍面临若干挑战...” → ✅ 改成“不过这个方法还有一些问题，比如高频噪声还没有完全滤掉”，保留问题，但不要写成漂亮的挑战总结。

#### 规则 L5：按真实检测报告处理“高风险但不空泛”的段落

真实 AI 检测报告显示，高风险片段不一定含有“具有重要意义”“应运而生”这类明显套话。检测器同样会标记那些信息密度很高、但句式骨架过于规整的工程段落。处理这类段落时，不要只做同义词替换，也不要盲目塞更多参数。

**高风险模式**：

- **文献综述连续罗列**：多个作者或标准按“研究了/提出了/验证了/为……提供依据”顺序排开，段末用“提供参考、奠定基础、具有借鉴价值”收束。
- **发展链条过完整**：用年份串成“从概念、验证、成熟到落地”的故事线，结尾再概括“完整演进路径”。
- **功能模块流水账**：连续使用“由……组成、负责……、用于……、实现……功能”，像说明书摘要。
- **参数结论过圆**：只有“满足要求、覆盖工况、留有裕量、安全储备充足”，缺少取值口径、保守假设或失效边界。
- **安全规范口吻成串**：一段内多次出现“应、必须、禁止、立即停止”，像规范条文改写而不是论文分析。
- **结论机械枚举**：按“第一、第二、第三”复述各章工作，每条都以“能够提高、具有价值、满足要求”结尾。
- **英文原文直译**：保留 typical、should、in conclusion 等英文说明文骨架，即使中文译文流畅也容易被判高风险。

**改写动作**：

1. 先定位报告中 80% 以上片段，按风险概率排序，不按章节顺序平均用力。
2. 对文献综述，每段只保留一个主线问题；文献不要整齐排成“研究了、提出了、验证了”，可以写成“前面的研究主要看了……，后面有学者又把……加进去”。
3. 对功能模块段，不要连续写“模块A负责B”。可以按普通说明写成“这个部分主要用来……，另一个部分则是……，两者配合以后才能完成……动作”。
4. 对参数段，补足取值前提和边界条件，但不要写得过度精炼。可以把“三缸合力取”写成“三个缸的合力取”，把“该值高于计算载荷”写成“这个数值比前面算出来的载荷高了”，让句子更像普通学生在解释计算结果。
5. 对安全段，把命令式“应/必须/禁止”改成“如果……就……”“当……时，系统会……”这类普通说明。规范条文可保留，但不要把整段写成操作规程。
6. 对结论段，减少整齐的“第一、第二、第三”复述，可以写成“从前面的设计可以看出……，不过实物验证还没有做，后面还需要继续检查……”。 

**改写示例**：

**输入（报告高风险）：**

```latex
3根并联总推力约589 kN，覆盖摆角满载工况并留有约47%的裕量。
```

**输出（报告导向改写）：**

```latex
在满载偏载这个工况下，对摆角缸进行了校核，三个缸的合力取$589\,\mathrm{kN}$。
这个数值比前面算出来的载荷高了约47%，多出来的这部分主要是为了应对支链同步误差，还有岩料冲击时可能出现的短时峰值；如果后续实测压力长期接近溢流设定值，就不能只靠这部分裕量了，还需要重新校核缸径，或者把摆角速度降下来。
```

**变更说明：** 原句有参数但太像结论标签；改写后补出校核工况、裕量用途和失效边界，同时把“三缸合力”“该值高于”这类精炼写法改成“三个缸的合力”“这个数值比前面算出来的载荷高了”等更普通的学生写法。

#### 内容逻辑类改写示例

**输入（AI 味道）：**

```latex
现有研究表明，振荡截割技术在硬岩破碎领域具有十分重要的工程应用价值。
尽管取得了一定的进展，但该领域仍然面临若干挑战，包括刀具磨损、粉尘控制和火花灾害隐患。
```

**输出（普通学生稿效果）：**

```latex
Hood 等\cite{hood2005}在2005年提出了振荡截割的概念，这个方法主要是利用岩石抗拉强度比抗压强度低很多这一特点，
让岩石更容易沿着拉伸面产生破裂。不过在UCS$>100\\,\\mathrm{MPa}$的工况下，镜型截齿磨损还是比较快，
所以MC51后面才转向采用碟盘刀具。
```

**变更说明：** 删除“现有研究表明”模糊归因，改为具体学者引用；删除“具有十分重要的工程应用价值”空泛声明；同时用“这个方法主要是”“不过”“还是比较快”等普通承接降低精炼感。

### 二、语言表达类（Language & Expression）

从词汇选择到句式节奏，消除 AI 生成文本的语言模式。

#### 规则 E1：降解“宏大叙事”与“空泛表达”

**敏感词**：应运而生、为了能够有效解决、重大难题、彻底解决、卓越性能、显著优越性、具有十分重要的工程应用价值、极大地提升、有效地改善、作为...的关键

**操作**：

- 砍掉起手式废话 → “为了能够有效解决...重大难题”“应运而生”不要保留，可改成“针对这个问题，本文主要做了……”。
- 降级绝对化词汇 → 将“彻底解决”“卓越性能”改成“有一定改善”“效果比原来好一些”“基本可以满足要求”。
- 去除空泛呼吁 → “具有十分重要的工程应用价值”不要写，改成“对后面选型和计算有一定参考作用”这类普通说法。

#### 规则 E2：替换“AI高频敏感词组”

**操作**：

- 运行 `check_text.py` 获取完整敏感词替换字典。
- 替换时不要追求高级词。优先把高频词换成普通学生常用表达，例如“显著提升”改为“有明显提高”，“优化”改为“改进”，“核心”改为“主要”。

#### 规则 E3：提振突发性（Burstiness）与扰动困惑度（Perplexity）

**操作**：

- 提振突发性 → 不要只写整齐长句。可以穿插“这一点比较关键。”“这里还要注意。”这类短句，但不要写成聊天语气。
- 扰动困惑度 → 保留一点不那么精修的承接，如“这个地方算起来比较麻烦”“所以这里采用了比较保守的取值”，让文字不像一次生成的模板段。

#### 规则 E4：根治“同义词循环”与“虚假范围”

**敏感词**：在某种程度上、从...到...（虚假范围）、一定程度上、某种意义上

**操作**：

- 核心术语不要乱换，但外围表达可以变普通。比如“执行机构”可以在后文写成“动作部件”，“控制策略”可以写成“控制办法”，只要不影响含义。
- 拆解虚假范围词 → “在某种程度上”“某种意义上”不要机械保留，可改成“有一定影响”“对结果有一些作用”。

#### 规则 E5：削减“填充短语”与“过度限定”

**敏感词**：为了实现这一目标、值得注意的是、总的来说、可以说、基本上、似乎、在一定程度上、具有...的能力

**操作**：

- 修剪填充废话 → “为了实现这一目标”“值得注意的是”“总的来说”可以删，也可以换成“为此”“这里需要说明”“从前面结果看”。
- 过度限定不要全删。普通学生稿里可以保留“基本、比较、一定程度上”这类词，但不能用它们掩盖没有依据的结论。
- 拒绝通用积极结尾 → “具有广阔的应用前景”改成“后续如果做样机试验，还可以继续验证它的使用效果”。

#### 语言表达类改写示例

**输入（AI 味道）：**

```latex
此外，模糊控制策略的引入显著地提升了系统性能，具有广阔的应用前景。
值得注意的是，该算法不仅能够有效地改善响应速度，而且在一定程度上降低了超调量。
```

**输出（普通学生稿效果）：**

```latex
引入模糊规则以后，系统的超调量从$12.3\%$降到了$4.7\%$，调节时间也缩短了约$40\%$。
不过这个方法也不是没有代价，前期需要离线整定大约40条模糊规则，现场调参用了两个工作日左右。
```

**变更说明：** 删除“此外”“值得注意的是”“不仅…而且…”“具有广阔的应用前景”；保留参数，同时加入“以后、也、不过、左右”等普通承接，避免写成过度精炼的技术结论。

#### 规则 E6：避免使用“是”（系动词回避）

**操作**：

- ❌ “该算法作为提升精度的关键体现” → ✅ “这个算法主要是用来提高精度的”

#### 规则 E7：打破“否定式排比”

**操作**：

- ❌ “这不仅仅是一次算法升级，而是控制理念的革命” → ✅ “这次算法改动主要改变了原来的控制办法”

#### 规则 E8：消除破折号滥用与连接词暴露

**操作**：

- **默认删除破折号** → 中文正文中的“——”和英文 em dash `—` 均视为高风险 AI 痕迹，除非确有语义断裂需要，不保留。
- **改用标点替代** → 解释、补充、递进关系优先改为逗号、分号或句号，确保前后衔接自然。
- **恢复自然连接词** → AI 常用破折号代替“即”“也就是说”“具体表现为”等连接，应按语义恢复为自然连接或直接拆句。
- **保留例外** → 仅在突然转折、插入语强打断、标题副题等场景保留；学术论文正文中即使保留，也必须确认比逗号、分号、句号更必要。
- **LaTeX 例外** → 数学负号、范围符号、复合术语连字符、表格横线、Markdown frontmatter 和命令参数不按本规则处理。

**注意**：所有示例中展示的破折号用法仅用于演示改写前的“AI痕迹”，不代表推荐用法。改写后应将破折号替换为逗号、分号、句号或自然连接词。

#### 规则 E9：中文版通用 Humanizer 补充规则

这些规则来自通用 Humanizer 写作模式，但已按中文工程论文语境改写：

- **无主语动作句**：句首“完成了、实现了、进行了、构建了、提出了”容易像机械摘要。补出主体、对象或工况，例如“控制器完成...”“试验台在...工况下实现...”。
- **权威感套话**：删除“本质上、从根本上讲、真正的问题是、核心在于、归根结底”。直接写机制、参数或约束。
- **引导式开场**：删除“下面我们来看、接下来分析、首先需要了解的是、本文将带读者了解”。论文正文不需要教程式开场。
- **口号式尾部否定**：删除“无需猜测、没有多余动作、无额外配置、不留死角”等口号尾巴，改成完整机制说明。
- **中文化后缀堆叠**：谨慎使用“数据驱动型、端到端式、全流程化、跨平台化、智能化、模块化、协同化、一体化”等连续修饰。保留必要术语，其余改为具体模块、接口或流程。
- **碎片化标题**：标题后不要紧跟“本节主要介绍...”或“性能很重要”这类重复说明。让标题承担标题功能，正文直接进入技术内容。

#### 规则 E10：普通学生稿效果（默认执行）

humanizer 的流程目标不是把段落打磨成更专业、更精炼的论文腔，而是让文本在核心事实、数值单位和结论方向不变的情况下，更接近普通本科生按资料整理出来的基础论文稿。检测效果和普通学生文风优先于规范、精炼和专业感。

**可执行动作**：

- **不大幅改字数**：总字数变化尽量控制在原段落的正负 10% 左右。主要靠语序调整、主谓宾重排、补主语和同义替换降低模型痕迹。
- **补足主语**：把“完成了、实现了、确定了、设计了”改为“本文完成了、控制系统实现了、设计中确定了、该机构采用了”等，避免空悬动作句。
- **降低精炼度**：不要把所有句子压成成熟论文式结论。可以保留一点重复说明和笨拙承接，例如“这样处理以后，后续计算时也比较容易对应”。
- **增加普通语助词**：不要把“的、了、把、这个、这样、前面算出来的、后面还需要”等全部删掉。适当保留这些词，能削弱过度压缩的模型味。
- **弱化漂亮结尾**：删除“具有较好的推广价值、取得合理平衡、奠定基础”等圆滑收束，改成较朴素的“基本能满足本设计需要”“后续还需要实物验证”。
- **句式变换**：主动使用把字句、被动句、前置状语、短句插入，打散原文骨架。
- **普通同义词替换**：将“显著、核心、协同、优化、鲁棒性”等非必要高光词换成“明显、主要、配合、改进、抗干扰能力”等更普通的说法。可把“执行机构、控制策略、系统架构”等非关键表达改成“动作部件、控制办法、系统组成”等普通说法。
- **标点放松**：允许减少句号，多用逗号、分号把意思接起来。这样文本会显得没有那么干净利落，更接近新手论文稿。但括号不能放松，中文解释性括号仍要清理。
- **适度口语化**：可使用“这样一来、这里、基本、比较、还需要”等平实词，但不写成聊天语气。

**禁止动作**：

- 不把会影响结论的关键术语改错，例如 PLC、比例阀、滚珠丝杠、均方根法、额定载荷、UCS 等一般仍保留；若要弱化，可在前后文用普通话解释，但不要换成错误概念。
- 不把参数、单位、公式、标准号、元件型号改写成模糊说法。
- 不为了“普通”而加入“我认为、我觉得”这类第一人称主观表述。
- 可以减少句号，但不能把几层不相关意思硬串在一起，读起来仍要通顺。

**改写示例**：

**输入：**

```latex
通过底盘强度校核，Q355矩形管焊接框架具有较高安全裕量，能够满足低速重载运行要求。
```

**输出（普通学生稿效果）：**

```latex
本文对底盘强度也做了校核，算出来以后可以看出，Q355矩形管焊接车架还有一定余量，在低速重载运行时基本够用。
```

**变更说明：** 补出“本文”作主语，保留材料和工况，把“具有较高安全裕量”改成更普通的“还有一定余量”“基本够用”。

### 三、文本结构类（Text Structure）

只处理正文结构和 AI 排版痕迹。LaTeX/Markdown 专属格式规范交给 `academic-format-cleaner`。

#### 规则 F1：打破“机械结构”与“流水线排版”

**敏感词**：本章将针对...开展工作、本节主要内容包括、下面将分别介绍、具体如下、如图所示

**操作**：

- 抹除章节预告 → 段首不要写“本章将针对...开展工作”，可直接写“本章主要对……进行设计”，但后面马上接具体内容。
- 消灭八股列表 → “名词+冒号+长篇解释”的清单体要改成普通段落，可以有一点重复和承接，不必压成很漂亮的一句话。
- 打破看图说话 → 不要写“如图所示”后马上来一段说明书式解释，可改成“图中可以看到……，这里主要用来说明……”。

#### 规则 F2：修复“标点暴露”

**操作**：

- 引号规范 → 禁用 ASCII 直双引号 `"..."`。中文正文引用、术语说明、反讽或非正式称谓使用中文弯双引号 `“...”`；双引号内部再引用时用单引号 `‘...’`；书名、论文名、标准名、法规名优先用书名号 `《...》`；代码、命令、变量、路径、文件名用反引号或 LaTeX 等宽命令，不使用引号；英文整句引用保留英文排版习惯，LaTeX 中优先采用 TeX 式开闭引号，不要写 ASCII `"..."`。
- 引号去留判断 → 仅用于真实引用、特指术语、非标准称谓或需要标明语义距离的词。单纯强调不要加引号，改用正常陈述。
- 括号清理 → 严禁堆砌连续括号，中文解释性文字直接化入正文或删除；只保留专业缩写、英文全称、标准号、型号、必要参数这类非留不可内容。

#### 规则 F3：抑制“过度修饰”与“格式暴露”

**敏感词**：实现着、体现着、展示着、彰显着（-ing式虚假深度）

**操作**：

- 清空表情与特殊装饰 → 论文里不要出现 Emoji，也不要机械地用粗体强调短语。
- 纠正“着”字虚假深度 → “实现着...”“体现着...”这类说法要改成普通动词，如“实现了”“表现为”“说明了”。
- 内联标题垂直列表 → 避免“名词：解释”的机械清单体，能融合成段落时优先融合，句子可以普通一点，不需要过度工整。

#### 格式结构类改写示例

**输入（AI 味道）：**

```latex
本章将针对液压系统开展设计工作。具体如下：
\begin{itemize}
  \item \textbf{泵源选型：} 采用负载敏感变量泵，根据负载压力自动调节流量。
  \item \textbf{阀组配置：} 采用比例方向阀实现流量精确控制。
\end{itemize}
```

**输出（普通学生稿效果）：**

```latex
本章的液压系统先对泵源进行了选型，泵源采用负载敏感变量泵，输出压力会跟随最高负载压力再加上$\Delta P_{\mathrm{LS}}$。
这样多余的流量就不用一直通过溢流阀发热了。三个缸分别配一套比例方向阀，用来对各自的流量和方向进行调节。
```

**变更说明：** 删除“具体如下”的清单体，但保留“本章”“先”“这样”等普通承接，使文字更像学生按设计过程写出来。

### 四、普通工程说明类（Engineering Characteristics）

保留必要的工程事实和取值依据，但表达不要像专业报告。优先写成“为什么这样取、这样取以后有什么问题、后面还要验证什么”。

#### 规则 T1：展现工程妥协与真实约束

**操作**：

- 承认技术限制 → 可以写“虽然精度提高了，但是计算量也变大了”，不用写成很成熟的技术权衡句。
- 体现硬件约束 → 可写“因为安装空间不够，所以这里没有继续增加部件”，比“受限于空间定额”更像普通学生稿。
- 展示参数权衡 → 保留具体数字，但解释可以普通，如“这个数值留得偏大一些，主要是为了后面运行时不太容易超载”。

#### 规则 T2：参数保留但说法放松

**操作**：

- 替换“大幅”“极大地” → 改为具体百分比或数值（如 $12.3\%$、$3.8\,\mathrm{s}$），但句子不要太短太硬。
- 补充基准对比 → 说明“比传统方案提升 37%”里的传统方案是什么，可以用“前一种方案”“原来的方案”这类普通说法。
- 保留单位与精度 → MPa、kN、Hz 等单位不能乱改，但可以把“该值”改成“这个数值”“这个结果”。

#### 工程特质类改写示例

**输入（AI 味道）：**

```latex
3-RPS并联机构极大地提升了截割系统的性能，彻底解决了传统悬臂式方案的困境。
```

**输出（普通学生稿效果）：**

```latex
3-RPS并联机构可以把空间位姿调整和高频振荡破岩这两个动作分开来处理。
不过三条支链不是完全对称的，协调伸缩时控制起来比串联悬臂更麻烦，单个油缸的跟踪误差需要控制在$\pm 0.5\,\mathrm{mm}$以内；如果误差再变大，末端轨迹经过雅可比矩阵放大以后，就可能超过刀具允许的偏差范围。
```

**变更说明：** 删除“极大地提升”“彻底解决”绝对化词汇；保留$\pm 0.5\,\mathrm{mm}$约束，但把“解耦、容差”等压缩表达展开成更普通的说明。

### 五、交流痕迹类（Communication Traces）

清除聊天机器人对话残留与 AI 身份暴露。

#### 规则 C1：清除“协作交流痕迹”与“AI身份残留”

**敏感词**：希望这些信息对您有帮助、好问题、您说得完全正确、请告诉我、截至目前、根据我最后的训练更新、虽然具体细节有限

**操作**：

- 剔除对话口癖 → 彻底删除“希望这些信息对您有帮助”、“好问题”、“您说得完全正确”
- 抹除知识时效免责 → 删除“截至目前”、“根据我最后的训练更新”
- 消除谄媚语气 → 删除过于积极、讨好的语言

#### 规则 C2：避免教学式过度解释

**操作**：

- 删除太基础的定义 → 如“液压系统是一种利用液体压力传递动力的系统...”这类教材开头不要写。
- 保留必要解释 → 如果术语很关键，可以用一句普通话解释，不要用括号堆满中文定义。括号只留英文全称、缩写、型号、标准号和必要参数。
- 不要过度教学 → 不需要把每个概念讲给外行听，但可以写成“这里的作用主要是……”这种基础论文语气。

#### 交流痕迹类改写示例

**输入（AI 味道）：**

```latex
电液伺服系统（即一种利用液压油作为介质的伺服驱动装置）具有响应快、出力大、控制精度高的特点。
它在工业自动化中具有广阔的应用前景。
```

**输出（普通学生稿效果）：**

```latex
截割臂上的三个油缸都采用电液比例伺服驱动，额定压力取$31.5\,\mathrm{MPa}$，
行程为$\pm 150\,\mathrm{mm}$，这样可以满足截割臂升降和姿态调整时的基本需要。
```

**变更说明：** 删除“（即一种…）”这类教材解释；保留具体参数，同时用“都采用、取、这样可以满足基本需要”这类普通表达连接起来。

## Part 2：普通学生稿口吻

避免 AI 模式只是工作的一半。现在的目标不是“写得更高级”，而是让段落像学生自己根据资料慢慢整理出来，有一点不精炼、有一点重复，但核心意思还能看明白。

### 仍然像 AI 稿的迹象（即使技术上“干净”）

- 每个句子长度和结构都相同，看起来太整齐。
- 一直用“显著、核心、关键、系统性”等词，像模型在总结。
- 没有“这个地方、前面计算、后续还需要”等学生写作常见承接。
- 读起来像产品新闻稿、说明书摘要或维基百科文章。

### 如何增加普通学生稿感觉

1. **用普通承接**：适当加入“这个地方、这样一来、前面已经算出、后面还要验证”等词。
2. **别太压缩**：把“三缸合力”“该值高于”这类压缩说法展开成“三个缸的合力”“这个数值比……高了”。
3. **保留参数但解释普通**：数值和单位不乱改，解释时可以写“这个数值留得大一些，主要是为了保险”。
4. **允许一点笨拙**：完美的结构感觉像算法。可以保留一点重复和不够精炼的表达，只要不变成口水话。

## Part 3：非正文区域保护原则

本 skill 可以读取 LaTeX/Markdown 文件，但只改正文。格式错误、引用位置、命令断行等问题由 `academic-format-cleaner` 处理。

### 禁止全局替换

禁止使用 replaceAll 修改 LaTeX 命令。缺失反斜杠时（如 `includegraphics`），只在当前单词前补全 `\`。

### 排版环境绝对保护

绝不修改、删除或翻译任何以 `\` 开头的命令和环境。特别注意：

- `ctexart` 中文字体设置命令（`\zihao`、`\songti` 等）
- `\begin{}`/`\end{}` 环境声明
- `\label{}`、`\ref{}`、`\includegraphics{}` 等交叉引用命令

### 数学体系免疫

`equation`、`align` 等数学公式环境块内部的字母推导、等式演算 **绝对禁止修改**。

### Source Marker 绝对保护

`[文献题名]`、`[网络资料: 检索词或网页标题]`、`[标准规范: 标准号或规范名称]`、`[Mxx]`、`[参考文献]` 等方括号标记是工作稿中的引用锚点，**不是正文内容，绝对禁止修改**。

规则：
- 不动 marker 的方括号（`[` `]`），不动方括号内的任何文字。
- 不缩写题名（如 `[基于神经网络的悬臂式掘进机自适应截割控制系统研究]` 不能缩为 `[神经网络...掘进机研究]`）。
- 不翻译题名（中文题名不动中文，英文题名不动英文）。
- 不删除 marker，不将 marker 改写成其他形式。
- 润色时只改 marker **前后**的连接词和句式。若 marker 所在句子需要大幅重写，先删除整个句子，再把 marker 原样插入改写后的等价位置。

### 格式问题转交

发现 `\cite{}` 位置、百分号转义、命令参数跨行、Markdown frontmatter 或代码块围栏问题时，不在本 skill 内展开修复，转交 `academic-format-cleaner`。

## 使用说明

1. **改写时参考**：按五大类规则逐段扫描，结合普通学生稿口吻要求
2. **敏感词检测**：运行 `python scripts/check_text.py <file>` 获取完整敏感词列表和位置
3. **自检**：运行 `check_text.py` 即为自检，无需手动对照检查清单
4. **格式支持**：
   - LaTeX 文件：`python scripts/check_text.py paper.tex`
   - Markdown 文件：`python scripts/check_text.py paper.md --format markdown`
   - 纯文本文件：`python scripts/check_text.py draft.txt --format plain`
