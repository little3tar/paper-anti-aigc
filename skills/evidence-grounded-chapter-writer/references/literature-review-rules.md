# 文献综述写作规则

本文件为中文工程论文的引言和文献综述章节提供证据驱动写作指导。

## Evidence Map 格式

每行一条可用来源：

| Source ID | 引用 | 来源类型 | 关键发现 | 可支撑论点 | 对应段落 | 风险 |
|---|---|---|---|---|---|---|
| FL-01 | [题名 作者 年份] | 期刊/标准/专利/用户材料 | 摘要级发现 | 具体论点 | §1.1 P2 | 直接/间接 |

规则：
- 优先使用用户文献池，不编造。
- 一条引用支撑一个具体论点，不泛泛引用。
- 间接支撑标注 `Risk: indirect`。

## Paragraph Blueprint

每段定义：

```markdown
### Paragraph N
- 角色：背景 / 方法族 / 局限 / 空白 / 贡献
- 主论点：
- 证据来源 ID：
- 转折或衔接：
- 禁止内容：
```

## Anti-Enumeration Gate

文献综述段落不能在 review 时被误判为"罗列"。每段必须合成以下至少两项：
- 一个工程问题条件
- 一个方法族或技术路线
- 一个多篇文献共享的局限
- 一个与本文方法的直接桥接
- 一个有引用的技术边界

如果一段可以转成表格行而不损失含义，则还不是论文正文。

## 中文工程论文 Introduction 模式

1. **工程背景与意义**：应用场景、行业痛点、规范要求，由基础文献或综述支撑。
2. **现有技术路线**：按方法族分组（不按论文列表），每组包含：代表方法 + 关键技术特征 + 已解决问题 + 遗留瓶颈。
3. **瓶颈级联**：各路线之间的关联和未覆盖的边界。
4. **研究空白**：本文聚焦的具体问题，与前述瓶颈直接对应。
5. **贡献边界**：用连贯段落写出贡献，不使用编号列表堆砌。每条贡献对应后续章节的验证手段。
6. **论文结构**：一句足以概括，不用长段逐章介绍。

## Introduction 与 Literature Review 的拆分/合并

- 中文工程硕士/博士论文：通常含独立"文献综述"或"国内外研究现状"章。
- 工程类 SCI 论文：通常将 Related Work 融入 Introduction，不大段独立。
- 拆分时：Introduction 聚焦问题驱动，Literature Review 聚焦方法族对比和批判。
- 合并时：Introduction 必须形成完整论证（背景→路线→瓶颈→空白→贡献），不能拆成两截。

## 正文污染防火墙

用户要求、过程说明、模板提示不得进入正文：
- "写得自然些" → 转化为句子调整
- "不要泛泛而谈" → 转化为具体证据位置
- "讨论提示"、"填这里" → 留在 plan 文件，不进入章节文件

## 工程设计段落句式轮换

工程设计章节（选型、校核、规范引用、功能模块说明）与文献综述不同——结论和参数必须准确，但描述方式容易陷入"模板复制"：连续多个元件使用完全相同的句式骨架。以下四类高频工程段落的句式轮换模板，在写连续同类段落时强制使用。

### 通用规则

- 连续 3 个同类元件（传感器、阀、模块等）的选型描述，禁止使用相同句式骨架
- 连续 3 句参数校核结论，禁止使用相同的"X 根并联推力约 XXX，比 YYY 高出 ZZZ"骨架
- 一段内禁止堆叠 3 个以上的"满足/符合/遵循 XXX 的要求/规定"
- 连续的功能模块说明禁止使用"XXX 负责/用于 YYY"的相同骨架

### 模板 1：元件选型段（传感器、阀、模块）

禁止模式：连续使用"选用 XXX，主要参数为：量程……输出……精度……防护等级……"

轮换骨架：
- A（先给参数再说明理由）："XXX 选的是 YYY 型，它的量程范围是……，选这个规格主要是因为……"
- B（一句话交代，后续展开）："XXX 方面，这里用了 YYY，后面的表列出了它的主要参数。"
- C（汇总式）："YYY 型和 ZZZ 型分别用于……和……，两类传感器的输出信号统一为 4~20 mA，这样 AI 模块的通道配置可以保持一致。"
- D（穿插式，选型+接线一起写）："XXX 采用 YYY，4~20 mA 两线制接入 SM531 的 IWx 通道，量程……"

### 模板 2：参数校核段（缸径、推力、功率）

禁止模式：连续使用"X 根并联总推力约 XXX kN，比 YYY 工况所需载荷高出约 ZZ%，留有 XX 余量。"

轮换骨架：
- A（数值+前提）："在满载偏载这个工况下，三个缸的合力取 XXX kN。"
- B（结果+边界）："这个数值比前面算出来的载荷高了约 ZZ%，多出来的这部分主要是为了……如果后续……就不够了。"
- C（对比式）："和传统方案的缸径（通常在 200 mm 以上）相比，ODC 低截割力的特点使这里可以选到 100 mm，压缩了约一半。"
- D（直接给出+条件说明）："按 XX 标准的第一系列，这里选了缸径 D=XXX mm，推力 YYY kN。这个推力在正常工况下够用，但如果到了极硬岩层，还需要在调试时验证。"

### 模板 3：安全规范引用段

禁止模式：一段内堆叠"满足……要求，符合……的规定，遵循……的条款。"

轮换骨架：
- 在开头用一句总述，随后分散引用不同规范
- 把规范引用嵌入到具体设计决策中，而不是在段末集中声明
- 对同一规范多次引用时，第一次给出全称+标准号，后续只说"按该规范的要求"

### 模板 4：功能模块说明段（软件/硬件架构）

禁止模式：连续"XXX 模块负责……，YYY 模块负责……，ZZZ 模块用于实现……"

轮换骨架：
- 按信号流/数据流方向叙述，把模块功能融入流程："信号从传感器进来后，先经过 XXX，这一步主要做……"
- 按设计决策叙述："在 XXX 方面，这里没有采用 YYY 方案，而是选择了 ZZZ，因为……"
- 按约束条件叙述："XXX 和 YYY 之间通过 PROFINET 交换数据，这要求 CPU 在每个扫描周期……"

### 表格前后正文约束

表格后的正文说明最容易写成目录体（逐行翻译表格内容）。写表格前后的正文时，让正文承担"为什么这样分配""这样分配的代价是什么"的解释功能，而不是逐行翻译表格内容。
