# 计算记录规则

正文中的公式推导和参数计算，先在 `.thesis-workflow/calculation-records.md` 中落盘（权威计算底稿），再选取关键步骤写入正文段落。records 是数据源，正文是叙述——不重复，正文直接引用 records 中的关键数值和公式编号。

## 文件位置

`.thesis-workflow/calculation-records.md`

## 落盘格式

| ID | 计算目的 | 输入参数与来源 | 公式 | 代入过程 | 结果 | 标准选型 | 适用章节 | 状态 |
|---|---|---|---|---|---|---|---|---|
| C3-01 | 推进油缸缸径 | P=25MPa [设计值], F=80~150kN [Boshoff 2023 估算] | D=√(4F/πP) | √(4×150000/π/25×10⁶)≈87mm | D=87mm | GB/T 2348→80mm | §3.2 | draft |

- **ID**：按章编号，如 `C3-01`
- **输入参数与来源**：每个参数标注来源类型（`[文献题名]`、`[设计值]`、`[标准规范: ...]`、`[用户材料: Mxx]` 等）
- **公式**：LaTeX math 格式
- **标准选型**：从计算结果到标准系列值的取舍，标注选型依据的标准号
- **状态**：`draft` / `confirmed` / `superseded`

## 状态管理与修正

计算记录的任何修正都遵循同一原则：**旧记录不删不覆盖，标 `superseded` 并追加新行**。以下情况均适用，不仅是参数变更：

| 修正类型 | 示例 | 操作 |
|---|---|---|
| 参数值变更 | 用户确认 P 从 25MPa 改为 28MPa | 旧行标 `superseded`，追加新行，新 ID 沿用原编号或子编号（如 C3-01a） |
| 公式修正 | 缸径公式应为 D=√(4F/(πP·η)) 而非 D=√(4F/πP) | 同上 |
| 代入/计算纠错 | 单位换算错误：25MPa 代入时写成 25×10⁵ 应为 25×10⁶ | 同上 |
| 标准选型调整 | 缸径从 GB/T 2348→80mm 改为 GB/T 2348→100mm | 同上 |
| 新增计算 | 细纲确认阶段用户补充了新计算需求 | 按章追加新 ID（如 C3-02），不涉及旧记录 |

每次追加新行时，在记录末尾附修正说明（如"原记录 C3-01 因单位换算错误于 2026-05-14 修正"）。保证每次参数选择和计算决策的完整链可追溯。

draft.md 工作稿中引用的计算记录 ID 同步更新为最新有效（非 `superseded`）记录的 ID。计算记录 ID 仅限内部追踪，写入主文件前清除。

## 审计使用

`reference-integrity-auditor` 对照此文件核验正文中计算数据的准确性，检查所用标准的核验状态。审计发现的数值不一致，同样按上述修正流程处理——标 `superseded`、追加新行、更新正文引用。

## 计算缺口主动补充（⭐）

正文中发现以下情况时，**必须主动添加新计算记录**，不得绕过：

- 正文出现计算类数值（缸径、推力、流量、功率、转速、压力等）但 `calculation-records.md` 中无对应记录
- 正文出现选型结论（如"选取 XX 型号"）但无推导过程支撑
- 正文出现设计参数取值范围但无来源或推导

补充流程：先按完整计算链（公式→符号表→参数来源→代入→结果→单位检查→标准选型）完成计算记录，再选取关键步骤写入正文。输入参数缺失时通过三级信息源（Zotero → 用户 → 网络）依次补齐。无法补齐的输入参数标为 `[设计假设: ...]`。

计算记录是正文数值的**唯一权威数据源**——正文中不得出现 records 中不存在的计算类数值。
