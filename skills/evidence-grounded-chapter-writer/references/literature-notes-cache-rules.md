# 文献笔记缓存规则

当章节引用文献较多（8+ 篇）或用户 Zotero 库中笔记/标注内容量大时，使用分批获取 + 磁盘缓存策略，避免一次性拉取全部笔记撑爆上下文窗口。

缓存文件是 AI 从 Zotero 拉取的**工作辅助材料**，不是用户提供的原始材料，因此放在 `.thesis-workflow/` 根下，与 `project-ledger.md` 同级，**不**放入 `evidence/`（用户材料目录）。

## 缓存文件

位置：`.thesis-workflow/literature-notes.md`

生命周期：创建（章节写作开始）→ 分批写入（写作过程中）→ 审计阶段读取校验 → 审计通过后清空（下一章开始前）。

### 文件结构

```markdown
# 文献笔记缓存

> 当前章节：§X.X 章节名
> 最后更新：2026-05-13T15:30:00

---

## [文献题名1]

- **来源类型**：期刊
- **作者/年份**：张三 2024
- **Zotero 标注**：
  - <标注色> 标注内容1（页码/章节）
  - <标注色> 标注内容2
- **Zotero 笔记**：
  - 用户笔记内容
- **获取状态**：已获取
- **已用于段落**：§X.X.X
- **提取时间**：2026-05-13T15:00:00

---

## [文献题名2]

- **获取状态**：无笔记
- **检查时间**：2026-05-13T15:05:00
```

### 获取状态标签

| 状态 | 含义 | 后续行为 |
|---|---|---|
| `已获取` | 笔记/标注已成功拉取并写入缓存 | 正常使用 |
| `无笔记` | Zotero 中该文献确实没有笔记或标注 | 跳过，不再重试。写作时仅用题名/摘要 |
| `获取失败` | Zotero MCP 不可用或网络错误 | 跳过，不再重试。在证据缺口清单中标注 |

### 写入规则

- 写入时不覆盖已有条目。同一文献如新获取了标注/笔记，**追加**到该文献条目下，更新 `最后更新` 时间。
- 每次写入完成后，在条目末尾记录提取时间。
- 写入缓存的内容需区分来源：标注（原文摘录）和笔记（用户个人理解）分开记录。笔记内容用作写作参考，**不替代对文献原文的核实**。

## 获取失败处理（关键约束）

### 每篇最多尝试 1 次

- 同一文献在一次章节写作 + 审计周期内，**最多尝试获取笔记 1 次**。
- 获取失败或确认无笔记后，立即在缓存中标记 `无笔记` 或 `获取失败`，后续阶段（写作后续节、审计）看到标记直接跳过，**不得重复尝试**。
- 不得因为"缺笔记"而卡在证据检索步骤循环重试。笔记是辅助材料，不是正文写作的必要条件。

### 无笔记时如何继续

| 场景 | 处理方式 |
|---|---|
| **写作阶段** | 以题名、摘要等公开元数据写作，在证据表中标注"该文献无可用的 Zotero 笔记" |
| **审计阶段** | 对照题名/摘要信息校验。无法核验的正文 claim 标记为"文献笔记缺失，无法交叉校验"，不自动升级为 P0/P1 |
| **全部文献均无笔记** | 正常写作，不阻塞。在章节交接报告中说明"本章文献无可用的 Zotero 笔记，证据支撑仅基于题名和摘要" |

## 分批获取协议

不要在证据检索阶段一次性拉取所有文献的笔记。按以下顺序分批：

### 第一批（细纲确认后立即获取）

获取**当前节**（细纲中即将开始写作的第一节）直接引用的 2-3 篇核心文献的笔记。写入缓存后立即用于第一节写作。

### 后续批次（每节写作前获取）

在开始写下一节之前，获取该节直接引用的 1-3 篇文献的笔记，追加写入缓存。

### 批次大小控制

| 场景 | 每批篇数 | 说明 |
|---|---|---|
| 完整章，文献 15+ 篇 | 2-3 篇/批 | 按节分批，每节写作前获取 |
| 完整章，文献 5-10 篇 | 3-5 篇/批 | 可一次覆盖 1-2 节 |
| 小节或短章，文献 ≤ 5 篇 | 全部 | 一次性获取不影响上下文 |

### 获取前检查

每批获取前，先检查缓存文件：
- 该文献笔记已在缓存中（状态 `已获取`）→ 直接读取缓存，不重复获取
- 该文献已标记 `无笔记` 或 `获取失败` → 跳过，不重试
- 该文献不在缓存中 → 通过 Zotero MCP 检查并获取笔记

### 用户授权

首次获取前询问用户：

> "检测到以下文献在 Zotero 中有笔记/标注：[首批文献题名]。是否允许我分批参考笔记内容？笔记将缓存到 `.thesis-workflow/literature-notes.md`，按节分批获取。"

- 用户同意 → 本章内后续批次沿用相同授权，不重复询问
- 用户同意但限制范围 → 仅在指定范围内获取
- 用户不同意 → 本章全程不使用笔记，仅使用题名/摘要等公开元数据

## 写作时使用缓存

### 每节写作前

1. 读取缓存文件，定位当前节相关文献的笔记条目（仅读取状态为 `已获取` 的条目）。
2. 从标注内容中提取**直接支撑当前段落论点**的关键发现。
3. 从笔记内容中获取用户的理解角度和关注重点，用于调整写作侧重点。
4. 写作完成后，在缓存中更新"已用于段落"。

### 上下文控制

- **不要**把缓存文件全部内容加载到对话上下文中。只读取当前节相关的 1-3 条文献笔记。
- 写作时引用缓存中的标注结论，使用 `[文献题名]` marker 标注来源。
- 如果某条标注内容需要原文核实，标记 `[待核实: 标注内容]` 并在审计阶段处理。

## 审计阶段使用缓存

`reference-integrity-auditor` 在验证正文 claim 时，同样无法直接读取 PDF 原文。缓存的文献笔记/标注是审计的关键参照物：

### 审计时读取

1. 审计开始前，检查 `.thesis-workflow/literature-notes.md` 是否存在。
2. 如存在，读取缓存中与当前审计段落相关的文献条目（仅读取状态为 `已获取` 的条目；标记为 `无笔记` 或 `获取失败` 的条目直接跳过）。
3. 对照缓存中的标注内容，验证正文 claim 是否与原文发现一致：
   - 正文声称"A 方法比 B 方法精度高 15%"但标注中无此数据 → 标记 P1
   - 正文引用的结论与标注中的方向相反 → 标记 P0
   - 正文 claim 在标注中有直接支撑 → 标记为"已验证（缓存）"
4. 标记为 `无笔记` 的文献无法交叉校验 → 在审计报告中标注"文献笔记缺失，无法交叉校验"，不自动升级为 P0/P1。

### 审计后清理

章节审计完成后，根据 `status.json` 状态决定缓存去留：

- `next_allowed = "humanizer"` 或 `"next-chapter"`（审计通过）→ 清空缓存内容，保留文件头和下一章占位：
  ```markdown
  # 文献笔记缓存

  > 上一章已完成。等待下一章写作。
  ```
- `next_allowed = "fix-evidence"`（审计未通过）→ 保留缓存内容，供修复阶段继续使用。修复完成并重新审计通过后再清空。
- 全部章节完成 → 清空缓存内容，保留文件（不删除），方便后续论文修改或增补章节时复用。

### 为什么清空而非保留内容

- 笔记缓存是**工作辅助材料**，不是正式产物。跨章保留过时缓存可能在新一章写作时被误用。
- 清空缓存为下一章释放空间，每章重新按需获取，确保笔记内容与当前写作目标匹配。
- 如需长期留存笔记参考，应通过 Zotero 本体管理，而非依赖此临时缓存。
- **不删除文件**：保留空文件避免反复创建，后续使用时直接写入即可。
